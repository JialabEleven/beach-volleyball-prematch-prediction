# Response to Reviewer 1 — Major Comment 2

Submission-ready draft after attaching the accompanying ZIP and applying the manuscript changes. Insert final supplementary-file/table and page/line numbers. This preparation step does not publish a repository or modify the Word manuscript.

**Comment:** Please specify the exact dataset version, download date, filtering criteria and procedure for reconstructing the 85,509 records; clarify the source and coverage of 2022 observations and retained matches by year; and provide accessible feature-construction, chronological-validation and model-evaluation scripts where permitted.

**Response:**

Thank you for this suggestion. We have clarified the data provenance and cohort-construction procedure and provide an accompanying Supplementary Reproducibility Package containing the analysis scripts, environment specifications, data manifests, annual sample counts, documented execution commands and validation results.

**Dataset version and download date.** The modeling source was the complete archive at `data/full_archive/full_archive.csv` in the BigTimeStats beach-volleyball repository. Retrospective verification established that our local complete archive and local 2022 yearly file have the same Git blob IDs as the corresponding files at commit `0fa423c5704de46a8cf0d9b8b542c694c0ae2276`, dated 29 September 2022. We provide the fixed commit URL, GitHub file-object metadata and SHA256 checksums. The complete archive's SHA256 is `b1a4ce4b90cb76fef5e47b4037f3aa86d8f43e57990c185187df0466f4a14e3d`. The original author download date was not retained and could not be recovered; we state this explicitly. The commit date is identified as the public version date, not our download date.

**Filtering and reconstruction of the analysis cohort.** The complete local archive contains 85,509 rows and 65 columns. All 85,509 records were retained in the feature table; observations were not excluded through complete-case deletion. The audit found no exact duplicate full rows, and no deduplication was performed. The reproducibility entry point checks the raw-file hash, required fields, valid source dates and required event/player identifiers, and reports failures rather than silently dropping records. The feature builder parses the source dates, applies the documented deterministic source-date/year/match-number ordering, normalizes names, constructs outcome-independent canonical Team A/Team B assignments, and derives the 104 model predictors. Feature values are emitted before applying the corresponding record's outcome update. Missing feature values are retained during table construction and imputed during training using parameters estimated from the training partition. The source-date ordering remains subject to the chronology limitations addressed in our response to Major Comment 1.

The temporal split comprises 65,057 training records through 2017, 12,369 validation records from 2018–2019 and 8,083 test records from 2020–2022. The package supplies cohort-flow and year-by-circuit-by-gender tables, a 104-predictor inventory, and scripts for rebuilding and checking the feature table. The source archive covers dates from 16 September 2000 to 23 September 2022; these are source-event dates, not verified individual match dates. We do not claim that the public archive exhaustively covers every AVP/FIVB match or that upstream collection filters can be reconstructed from the local archive.

**2022 observations.** The 2022 records are present in the identified public repository version. The analysis contains 4,206 records from 2022, compared with 719 from 2020 and 3,158 from 2021. Retained counts for every year from 2000 to 2022, with circuit and gender breakdowns and source-date ranges, are provided in the supplementary tables. Comparison of the complete archive and yearly files identified a small number of differences in player-name encoding and country metadata; we report these differences and identify the complete archive, rather than a concatenation of yearly files, as the authoritative modeling input.

**Accessible code and limits of numerical reproduction.** The supplementary ZIP includes the feature builder, chronological checks, tournament-freezing implementation, model-evaluation scripts, paired cluster-bootstrap code, dependency specifications and README instructions. A portable entry point supports pinned data acquisition, hash verification, cohort reconstruction, feature construction and matched CatBoost evaluation. Third-party raw data can be obtained from the fixed upstream version and verified against the supplied hash. The package also provides archived result tables and fixed test predictions so that uncertainty analyses can be reproduced without retraining all models. Archived scripts with machine-specific default paths have those path prefixes normalized; the changes are documented in a script manifest.

We distinguish successful input/feature reconstruction from exact reproduction of historical model metrics. The matched original-pipeline rerun did not exactly reproduce the original main-table AUC, and this discrepancy is reported rather than presented as resolved. Historical model-comparison and interpretation scripts are supplied, while the package's validation report identifies which execution paths were actually tested. We do not claim that all historical software environments or model fits have been reproduced exactly.

These additions appear in Methods (Data source and prediction task; Data preprocessing and time-aware split; Evaluation metrics and implementation), the Data and Code Availability statement, and the accompanying supplementary reproducibility materials.
